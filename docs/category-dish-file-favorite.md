# 分类、菜品、文件与收藏闭环基线

> 更新日期：2026-08-08

## 1. 分类与可见性

- 用户端只返回 `active` 分类，按 `sort_order` 升序排列。
- 用户菜品列表、菜品详情和收藏列表同时要求所属分类为 `active`；隐藏分类不会修改菜品自身上下架状态，重新显示分类后原状态自动恢复。
- 分类创建和更新使用不同请求 DTO，允许单独切换状态；名称会去除首尾空白。
- 分类下存在未删除菜品时返回 409，不允许删除；批量排序拒绝重复或不存在的 ID，并在事务中原子完成。

## 2. 菜品状态与删除

- 用户可见条件为：菜品未删除、`is_listed=true`、所属分类为 `active`。
- `normal`、`out_of_stock`、`unavailable` 三种状态均可展示；只有 `normal` 可以下单或加菜。
- 管理端使用独立详情接口读取下架或隐藏分类中的菜品，避免编辑页误用用户可见性接口。
- 菜品名称在未删除数据中唯一。批量上下架去重并使用事务，任一 ID 不存在时整体回滚。
- 删除使用 MyBatis-Plus 逻辑删除；订单明细保存 `dish_name` 快照，菜品删除后历史订单明细仍保留。

## 3. 图片只保存 fileId

持久化链路固定为：

`dish_info.image_file_id → sys_file.id → MinIO bucket/object key`

菜品表不包含 `image_url`、对象键或预签名 URL。创建菜品必须提交 `imageFileId`；后端校验文件存在、为图片且属于当前管理员。`DishVO.imageUrl` 和 `thumbnailUrl` 是读取时生成的短期字段，不允许客户端回传并持久化。

管理端上传接口为 `POST /api/common/file/upload`，multipart 字段名为 `files`，返回数组，其中每项包含稳定的 `fileId` 和用于即时预览的短期 URL。

## 4. 文件安全与一致性

- 单文件不超过 5MB，单次最多 5 个，文件名不超过 255 字符。
- 支持 jpg/jpeg/png/webp；以文件签名和可解析尺寸为准，不信任扩展名或客户端 Content-Type。
- 图片边长不超过 10000，像素总数不超过 4000 万。
- MinIO 桶在首次上传时按配置自动创建；数据库保存服务端识别后的 MIME 类型。
- 多文件上传失败时补偿删除本次已上传对象，避免数据库事务回滚后遗留对象。
- 文件模块通过 `FileReferenceChecker` 扩展点检查上层业务引用，不反向依赖 app；菜品仍引用文件时删除返回 409。
- 只有上传人可以将文件绑定到新菜品、替换菜品图片或删除未引用文件。

## 5. 收藏语义

- 只有当前用户可见的菜品可以收藏；下架、删除或隐藏分类中的菜品不能新增收藏。
- 收藏记录保留后，菜品暂时不可见时不会出现在收藏列表；恢复可见后自动重新出现。
- 收藏列表返回 `DishVO`，包含动态图片地址和当前状态，支持直接复点。
- 添加收藏使用数据库原子 `INSERT ... ON CONFLICT DO NOTHING`，重复点击或并发请求保持幂等；取消收藏同样幂等。

## 6. 验证

- `ImageTypeDetectorTest` 验证内容识别、扩展名伪装和损坏图片拒绝。
- `DatabaseBaselineIntegrationTest` 使用真实 PostgreSQL 15 与真实 MinIO，覆盖上传/预签名/删除、fileId 持久化、文件归属与引用、分类隐藏、上下架、状态、收藏幂等、软删除和历史订单快照保留。
